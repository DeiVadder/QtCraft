## QtCraft 1.0.0-rc.3 – release candidate for the playtest

The release candidate for QtCraft 1.0.0 (rc.1 and rc.2 produced no packages; their package checks failed on details of Qt 6.12 and of Ubuntu). It collects everything since 0.1.0 and is meant for the playtest. Feedback from the playtest goes into 1.0.0. This is a pre-release; 0.1.0 stays the latest release until 1.0.0 is out.

### New since 0.1.0

- **Linux:** an AppImage for x86-64 with the game and the dedicated server in one file (`--headless` starts the server). Qt, FFmpeg, ICU and the xcb helper libraries are bundled; OpenSSL, PulseAudio, D-Bus, Wayland and X11 come from the system.
- **Menus and screens:** inventories and all machines (workbench, furnace, chest, stonecutter, anvil, enchanting table, trading, creative) share one frame with a title, a close key, labelled slots and key hints. The main menu lists every world once, with a "…" menu to open its folder or delete it. Texture packs are grouped into active and inactive, and the character page is grouped.
- **Handbook:** pages scale with the interface, technical facts (ID, states, sound) are folded under "Technical", and creatures, biomes and features have icons.
- **Loading and start screens** show real progress.
- **Worlds** keep an index of every generated chunk.
- **Qt 6.12:** the packages now use open-source Qt 6.12.0. Frame times are unchanged within measurement noise against Qt 6.8.

### Worlds and compatibility

- Worlds from 0.1.0 open in this release candidate.
- Generator version 1 (0.1.0) stays frozen. Until 1.0.0 the world generator may still change. In a world created with this release candidate, chunks generated later by 1.0.0 may then differ at the borders from those generated now. For a playtest world that is acceptable; for a world to keep, wait for 1.0.0.
- Client and server must use the same release; 0.1.0 and 1.0.0-rc.1 cannot play together.

### Known limitations

- **macOS:** now needs macOS 14.4 or newer, because Qt 6.12 does. The app is not notarised: on macOS 15 and later try to open it once, then allow it under System Settings → Privacy & Security → Open Anyway; on macOS 14 right-click (Control-click) the app and choose Open.
- **Windows:** the program is not signed; SmartScreen asks on the first start (More info → Run anyway).
- **Linux:** the AppImage was built and played in a Fedora ARM64 VM. The x86-64 package from the release workflow has not been started on a real PC yet.
- **Sound:** the generated sounds and music have not had a dedicated listening review yet; that follows after the playtest.
