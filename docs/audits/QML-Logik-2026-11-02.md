# QML logic audit: what belongs in C++ (2026-11-02)

Read-only audit of `src/app/qml` (139 QML files, about 17 000 lines, no JS files) on `dev` at e0fc106.
Nothing was changed, built or run. Rules applied: CLAUDE.md (E-942 QML lean, E-688 enums and
rejected inputs), `docs/Review-Liste.md` (QML part), row 79.47.

**Left out because 79.47 covers it** (the Main.qml refactor running now): the 16 `LazyScreen` blocks /
`OverlayScreen`, the pause menu's overlay list (`pauseMenuOpen`, Main.qml:202, check-qml `enum-list`),
the advancements return path (`lastOverlay`/`advancementsReturn`, Main.qml:26-27, 224, 229-236,
check-qml `connections-write` ×2), the file split, and `PhotoNotice` -> `Notice`. Main.qml findings
below are outside that scope. Items marked **(adjacent to 79.47)** touch the same overlay rules and
should start only after 79.47 merges.

**Not counted as findings** (presentation): focus and scroll helpers (`firstTabItem`, `reveal`,
`focusRow`, `focusPending`, `holdsFocus`), enum -> `qsTr` text switches (`LoadingScreen.stepText`,
`AdvancementDetails.frameText/stateText`, `AnvilScreen.costText`, `EnchantingOffer.spoken`),
choice tables `{ text: qsTr(..), value: Enum.X }` (GraphicsPage, InterfacePage, CharacterPreviewPanel,
AdminLogPage, AdminOverviewPage, SlotScreen:159), `LineChart.niceScale`, `WorldLabels` placement,
`MapPreviewGroup` panning, zoom in AdvancementsScreen, `SidebarScreen.confirmReset` (a UI
confirmation), the `MainMenu` page switching (UI navigation, apart from C-7), and the
`OnScreenKeyboard` key rows.

Effort: S = under 1 h of agent work, M = a few hours, L = most of a package.
Risk: L(ow) / M(edium) / H(igh).
